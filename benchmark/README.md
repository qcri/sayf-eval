# sayf-eval benchmark registration (DRAFT — hold for release)

> **Status: DRAFT.** These artifacts register sayf-eval as a HuggingFace
> *Community-Evals* benchmark (a public leaderboard). **Do not push them until**
> the public-disclosure decision is made — they go live together with the PyPI
> release. Publishing a cybersecurity leaderboard is a deliberate dual-use call.

This folder holds everything needed to stand up the benchmark on the Hub:

- [`eval.yaml`](eval.yaml) — the benchmark spec (one sub-leaderboard per task,
  all 24). Generated by `sayf-eval benchmark-spec`; regenerate after task
  changes. Goes to the **root of the benchmark dataset repo**.
- [`DATASET_CARD.md`](DATASET_CARD.md) — the dataset card (repo `README.md`).
- [`REGISTRATION.md`](REGISTRATION.md) — the one-time HF steps + the
  `huggingface.js` framework-enum entry to PR.

## Go-live checklist (when disclosure is approved, with the PyPI release)

1. Decide the **public task subset** (some sub-tasks may stay internal). Regenerate
   `eval.yaml` with `sayf-eval benchmark-spec --tasks <subset>` if not all 24.
2. Create the dataset repo and push `eval.yaml` + `DATASET_CARD.md`:
   `sayf-eval benchmark-spec --push-to qcri/sayf-eval --public`.
3. Open the `huggingface.js` PR adding the `sayf-eval` framework (see REGISTRATION.md).
4. Ask HF to allow-list the dataset (registration is beta).
5. Publish per-model results: `sayf-eval eval-results … --submit-pr <model_repo>`.
